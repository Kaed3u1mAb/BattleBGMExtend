# BattleBGMExtend

作者：**枫海千叶**。

BattleBGMExtend 是基于[浮士德启动器（FaustLauncher）](https://github.com/f0lkskill/FaustLauncher/tree/main)的《Limbus Company》战斗 BGM 扩展插件，适用于 Windows x64。插件根据指定人格的 Buff 与回合条件自动替换战斗音乐，并按优先级保持播放。安装包自带原生 DLL，不依赖 WarpHook。

本仓库同时提供完整源码、构建与测试脚本，以及 `addon/BattleBGMExtend/` 中可安装的插件本体。

当指定人格满足 Buff、回合开始或 Buff 转化条件时，切换战斗音乐并锁定。本次战斗中，游戏的普通换曲、剧情插曲、阶段切歌、音乐停止请求不能覆盖该规则；只有优先级更高的插件规则可以替换它。

## 插件功能

- 指定人格获得 Buff、进入特定状态，或满足回合开始/结束条件时，切换到对应战斗 BGM。
- 换曲后阻止游戏覆盖；数值越大的规则优先级越高，拒绝同级与低级规则覆盖。
- 战斗结束、退出、失败或重试后解除锁定；支持托盘菜单连接、暂停和查看状态。
- 通过 `rules.json` 配置人格、条件、曲目和优先级，当前内置下列 9 条规则。

## 行为约定

1. **数字越大，优先级越高。** 高优先级规则生效后，低优先级和同优先级规则均不能覆盖；同优先级不会反复重播。
2. 规则触发后保持锁定。Buff 消失、单位死亡、进入下一回合或同一战斗的下一波，都不会自动降级或恢复原曲。
3. 正常结束、失败、手动退出、重试及离开战斗场景时解除锁定，允许游戏播放结算和菜单音乐。下一次战斗重新计算优先级。
4. 暂停、禁用、卸载插件，或启动器失去心跳超过 5 秒后解除拦截。战斗中暂停会尝试恢复原战斗播放列表；恢复插件后，如果条件仍成立，可以重新触发。
5. 只匹配场上的友方人格模型；不根据敌人同名、图鉴名称或后备队员触发。
6. 状态条件监听 Buff 事件并在主线程逐帧补查；回合条件只在对应回合流程判断。下回合生效的 Buff 不提前触发；连接时已持有的 Buff 可触发状态规则。李箱判断恰为 9 层，鸿璐的缺失条件不会在战斗初始化时触发。
7. 罗佳的预知眼转化按同一单位、同一回合记录。已有过热 Buff 不算新转化；回合结束等待动画与单位处理完成后换曲，不强制推进回合。暂停、退出和重试会清除尚未完成的转化记录；中途连接时，罗佳可读取游戏保留的本回合转化标记。
8. 音频资源创建失败时不先停止原曲，也不提高优先级门槛；日志会报告具体事件路径。若正式切换失败，会尝试恢复此前锁定曲或原战斗播放列表。

普通音量、静音、音效与语音设置仍由游戏控制。本插件锁定的是战斗 BGM 的选择与播放，不接管整个音频设备。

## 安装

将 `addon/BattleBGMExtend` 整个文件夹放到正在使用的 FaustLauncher 的 `addons` 中，然后重启启动器。已有 LimbusToolKit 和 FrameUnlocker 可以保留。

也可使用：

```powershell
./install.ps1 -LauncherPath 'C:\path\to\FaustLauncher'
```

首次安装后启用插件，通过启动器启动游戏。默认自动连接；托盘菜单提供「连接 / 恢复」「暂停」「查看状态」。规则触发后日志会显示 `BGM locked`、规则 ID 和优先级。

安装脚本原样保留已有 `addon_info.json` 和 `rules.json`；确需用发行版规则替换已有规则时使用 `-ReplaceRules`，脚本会先保存备份。更新原生 DLL 前需要正常退出游戏。重载 Python 入口不会替换已经进入游戏进程的 DLL。

## 配置与后续规则

运行时规则位于插件目录的 `rules.json`。源码中的默认规则位于 `src/rules.json`；构建会复制到安装目录。格式和后续条件文档模板见 [规则说明](RULES.md)。

支持持有 Buff、回合开始时精确层数、回合开始时缺失 Buff、Buff 转化后的回合结束四类条件，最多 32 条规则。详细格式见规则说明。

修改 `rules.json` 后，在启动器中重载插件或重启启动器。内置优先级为 6000–10000，数值越大越优先。

## 源码与构建

```text
src/scr.py                    启动器入口、配置校验、进程连接、共享内存、日志
src/battlebgmextend.c          主线程检测、原版音乐播放、优先级与生命周期拦截
src/bgm_layout.h               Python / C 共享协议
src/il2cpp_api.h               IL2CPP API 类型与别名顺序
src/il2cpp-api-names.txt        完整的 234 项混淆导出名基准表
src/rules.json                 默认规则
src/tests/                     加载器、规则、原生钩子和生命周期测试
src/third_party/minhook/       MinHook 源码及原许可证
addon/BattleBGMExtend/         可直接安装的插件本体
```

需要 x64 MinGW-w64 GCC、Python 3 和 PowerShell：

```powershell
./test.ps1 -Compiler 'C:\mingw64\bin\gcc.exe' -Python 'python'
./build.ps1 -Compiler 'C:\mingw64\bin\gcc.exe'
```

游戏方法、字段、命名空间和签名在运行时通过 IL2CPP 查询；没有写死游戏方法 RVA。所有游戏对象访问和音乐切换在 Unity 主线程执行；跨回调保留的 StageModel 和转化跟踪单位使用指针宽度的 Unity 6 GC handle。0.2.0 使用共享协议 v2，更新后需重启游戏和启动器。原生钩子保留至游戏进程结束，关闭功能通过共享开关与心跳实现。

MinHook 的许可证随源码及安装目录中的 `THIRD_PARTY_LICENSES.txt` 一起提供。

已进行 Python 加载器/配置测试、真实 MinHook 的 Buff 与音乐函数 ABI 测试、优先级及清理回归检查，并离线使用本机 FMOD 音频库在 NOSOUND 模式下创建并启动全部 9 首目标曲目。12 项 Python 测试及 91 项原生断言通过，另完成 50 项方法/字段核对。方法要求也核对了 dump 中的真实命名空间、参数和返回类型。

**尚未进行游戏内实测。** 离线检查不代表所有剧情、异想体脚本或后续游戏版本都已验证。游戏内验收建议见 [规则说明](RULES.md)，需检查三个回合条件、不同优先级覆盖和退出战斗恢复音乐。排查时可使用启动器日志中的 `[BattleBGMExtend]`、事件路径和错误方法名。
